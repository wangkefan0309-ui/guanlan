# 删除、恢复与批量阅读管理

v0.19.1 在“我的材料”提供单篇删除、“批量管理”、未读筛选和回收站。

单篇点击“删除材料”，确认后移入回收站；Escape 或“取消删除”可取消。批量管理可逐篇勾选，也可“全选筛选结果”，后者覆盖全部分页。按文章计数，同篇全部历史版本一起移入回收站。改变筛选或离开页面会清空选择，避免误操作。

回收站支持单篇或批量恢复，保留各版本、阅读状态、位置、正文批注和来源原件。这里是工作台中的可恢复删除，文件暂留原路径，不释放磁盘空间。已有讨论、RAW、Wiki 和已提交的知识任务保留；不会通过删除文章撤销已经提交的模型工作。

删除按本阅读库保存记录，不改共享后台的材料账本。后续同步跳过同一来源身份的新旧正文；用户手动重复导入时提示先恢复。已删除链接也不在推荐页展示。恢复后继续按已有版本去重。

“标记已读”“移到稍后读”“标记未读”批量保存阅读状态并保留阅读位置。选中文章仍有未保存的阅读草稿时先阻止删除或批量进度操作，保存后再继续。索引保存失败保留原列表，显示实际错误，用户可以明确重试。

探索推荐中已经收录的材料也能直接“标记已读”，按规范化原链接关联当前库的活动材料，沿用同一进度保存与草稿保护。未收录或已删除的推荐不提供快捷已读；不改推荐记录或替换当天条目。入口说明见[探索操作](active-exploration.md#打开收录和知识接续)。

历史精选只保存原材料版本引用。删除后历史卡片隐藏，恢复后仍使用原引用；已读退出但当天不补位，不删除历史曝光记录。材料的新版本不会替换当日已保存的引用，详见[历史精选](history-highlights.md)。

核心数据是阅读索引中的 `items` 与 `trash`，后者保留 `{item, deletedAt}`；两者的正文和原件路径都先校验再缓存。删除、恢复、批量进度和同步复用同一 ReadingLibrary 串行队列，每次批量只提交一份索引，不逐文件删除。切换阅读目录不搬迁回收站。

验证入口：`npm run verify:material-management`。使用 validation-vault-v0.1、独立服务和模拟模型，不向正式后台导入测试文章；正文、批注和原件逐个校验哈希。当前运行见项目状态。
