# Claudian、文字稿与 RAW/Wiki 接续

现行程序与运行版本见项目状态。2026-10-23正式插件v0.22.1已对Claudian 2.3.27完成本地接口验证；同版隔离材料会话链路采用模拟发送，不代表真实模型或RAW/Wiki加工通过，见验收。既有完整知识加工证据来自`validation-vault-v0.1`的Claudian 2.3.17；正式接续仍核对该Vault的`fanos-raw`真源。首次材料同步见接入回执，历史背景见架构交接。

v0.14.0将主动导入放在“添加材料”，阅读和接续操作放在选中材料的详情；“知识接续”按真实状态筛选并提供回到讨论的入口。原件、覆盖说明与恢复操作折叠显示，原手动RAW交接准备继续保留。后续直达入口沿用同一知识模型、正式协议及未知不重发规则。

## 日常怎样使用

Claudian 更新后若出现“尚未验证接续接口”，打开 **连接与设置 → Claudian 接续 → 验证 Claudian 接续**。检查通过后立即保存并恢复材料接续入口，不用再点“保存配置”。首次验证会按需打开空白聊天页；本地验证检查当前已加载版本的会话、队列、草稿保护和发送接口，不发送聊天消息或调用模型，不证明模型连接和 RAW/Wiki 加工已经成功。若提示先打开聊天页，手动打开 Claudian 的任意聊天页再验证；接口不兼容时保留原因及材料，需适配新版接口后再用。

回执保存在工作台插件自身目录 `claudian-compatibility.json`，与连接设置草稿独立；工作台重载会读取该回执。Claudian 再次升级或工作台适配契约变化时重新验证；回执损坏或无法读取时不会放行未知版本，可重新点击验证恢复。内置历史实测版本 2.3.17 继续可用。验证可以读取当前草稿的结构，但不修改、发送草稿或新建关联会话。

| 内容从哪里来 | 操作 | 随后能做什么 |
| --- | --- | --- |
| 自己找到的文章、文件 | 添加链接或导入文件，选择“导入并交给 Claudian” | 自动创建该材料的关联会话，送入笔记引用和指定任务 |
| 订阅推送 | 点开文章，选择“交给 Claudian 处理” | 使用已保存版本和首份原件，不重新抓取覆盖 |
| 历史精选 | 打开原材料详情，再选择讨论或直达Wiki | 沿用清单保存的原版本、批注和关联会话；仅推荐或标记已读不触发知识任务 |
| 探索推荐 | 卡片上选择“交给 Claudian 处理” | 先取得实际正文或字幕，再进入同一接续；仅推荐摘要不能当全文 |
| YouTube、B站视频 | “取得视频文字稿”或“取得文字稿并交给 Claudian” | 尝试公开字幕；平台限制时明确失败，可以导入自己的字幕 |
| MinerU 等生成的 PDF 转换稿 | 先保存 PDF，再选“补充 PDF 的 Markdown 转换稿” | 原 PDF 保留，转换稿保存为独立正文版本；随后选新版本加工 |
| 已选入的材料 | “知识接续”中选材料，点击“继续 Claudian 讨论” | 回到原会话；不必新建对话、复制文件路径或投放 Inbox |

默认仍交付讨论底稿。在 Claudian 里补充、质疑、修正，确定后明确说“归纳并写入当前 Wiki”。本接续任务把写入范围限定在 08；fanOS 需要另外说明具体目标与改动并获授权。没有把阅读完成、赞同一句话或短导读自动变成知识归纳。

无需讨论时，链接/文件导入弹窗提供“导入并直接写入 Wiki”；订阅、我的材料与知识接续详情提供“直接写入 Wiki（不讨论）”。探索推荐的更多操作也提供该入口；视频先取得实际文字稿，再进入直达接续。普通导入与原讨论入口继续保留。

点击直达按钮就是对指定材料在 `08_LLM Wiki` 内客观整理及最终归纳的明确授权。Claudian 仍校验原件、版本、来源和产物，优先补充已有主题；不结合阅读批注或聊天中的个人想法，不把作者观点冒充已验证事实或帆确认。按正式协议追加 `discussion/skipped`，保存实际 Wiki、来源档案和主题地图，再保存 `finalize/completed` 与 `finalized`。涉及原件、版本或用户修改冲突时停止并报告；不扩大到 fanOS、Inbox、个人记忆或根规则。

选择在材料回执中保存为 `mode=direct-wiki`，排队、重启和自动出队沿用首次选择。已提交讨论任务的材料可明确追加一次直接归纳请求，复用原会话和同一 run；正在加工时先保存 `wikiRequestedAt` 并排队，发出前保存 `wikiSubmittedAt`。重复点击或结果未知不重发；已完成 Wiki 不再追加任务。取消待处理仅取消未发送的意图。显式跨会话恢复仍首轮只读，同时撤销未发送的旧直达请求，需要用户后续明确给出归纳指令才能完成Wiki。

连续选入多篇时，当前 RAW 任务结束后再提交下一篇，减少多个 Agent 同时改主题页与地图的机会。自动出队也等待当前其他聊天的草稿、图片草稿和正在接收的回复，不切走输入焦点。待处理任务可以取消；阅读材料和原件保留。关闭 Obsidian 时不继续后台加工，重开后仅恢复已经明确选入、尚未提交的队列。已提交而结果未知的任务不自动重发。队列恢复限当前配置阅读库，其他目录的待办仍留在原目录。

## 文件与模型

阅读根目录可命名为 `09_Information Source`，包含全部收录材料及历史。普通导入先保存该阅读库；选择讨论或直达后，Claudian再校验并把指定原件复制到 `08_LLM Wiki/RAW`。08复用现有主题页、来源引用和地图，fanOS仍需具体目标授权。它们在同一Vault通过双链接续；工作台不全库扫描。更换阅读根目录不自动迁移材料或已有知识引用。

插件只写配置阅读目录中的接续笔记、正文快照和私有回执。接续笔记引用指定原件及用户批注，正文快照使用登记版本的正文，AI 短导读不混进原文。Claudian 校验原件后完成 RAW 首次创建，调用现行 `raw_pipeline.py` 登记与推进；工作台不自行生成 Wiki 或伪造 RAW 事件。

阅读目录通过已有文件夹选择与预览后显式保存；目录冲突、配置损坏、已使用目录移动/删除会暂停写入和自动出队。先恢复资料或另选独立库，核对后重新保存；切换目录不会搬迁旧队列、材料或RAW/Wiki引用。详见设置与存储。

Markdown、HTML、PDF、SRT、VTT 可主动导入。扫描 PDF 不会假装已 OCR；目前不内置 MinerU 服务。SRT/VTT 保留原字节和时间定位，偶发逆序或零时长的字幕保留句子、标记时间码待核对，不凭猜测修复。

RAW 使用 Claudian 当前选定的模型。测试读取到的是 Codex 提供方的 `openai-codex/gpt-6.1-sol`；工作台的 DeepSeek Flash 仍只承担原有短导读/探索筛选。桥接不会切换 Claudian 模型，选择 Flash 时会提示另选知识加工模型。

## Claudian 接法与恢复

桥接隔离在`src/plugin/claudian.ts`，使用Claudian内部的会话、笔记引用和原生发送控制器，不修改第三方源码。2.3.17是内置历史实测版本；其他版本须在设置中通过本地接口验证后使用，2026-10-23已核对2.3.27。升级后未验证或接口检查失败时暂停桥接，保存、阅读和手动RAW路线仍可用。接口检查只核对当前适配所需的方法及数据结构，不能保证未来版本的方法语义，实际任务结果仍以回执和文件为准。

材料身份和版本绑定 Claudian conversation ID。先保存会话身份，再保存提交意图，最后交给原生发送流程。同条目同版本重复点击只打开原会话；创建成功但绑定保存失败时，按关联接续笔记找回空会话。用户未发送的草稿保留。原会话被用户删除时提示从接续笔记恢复，不默默创建并重发。

Claudian 会把讨论写入同一 run 的 08 回执，换会话时可读回执恢复；原手动 `/raw resume` 路线也保留。工作台打开期间每20秒核对本地进度，不触发模型或平台采集。队列每15秒检查一次，已有 RAW 任务正在加工时不会反复切走当前聊天。

原会话被删除、原生提供方报告活跃写入者或无法继续时，可以明确点击“原会话无法继续：从回执恢复”。先核对已有RAW/run产物，再建立恢复会话并保留旧会话与身份；连续点击复用该恢复会话。首轮只读来源、Wiki和讨论回执，不重新登记、加工或推进事件；接下来正常提问或给出具体归纳指令。不能用这个按钮修复缺失或被改的原件、快照和Wiki产物，检查不通过时先恢复文件。

## 状态怎样核对

| 显示 | 实际依据 |
| --- | --- |
| 已排队 | 材料、原件、快照、接续笔记和队列意图已保存，尚未提交 |
| 已提交，等待 RAW 回执 | 已保存发送意图；尚不能断言模型已成功加工 |
| RAW 已登记 | 正式来源事件、同哈希 RAW 文件、来源档案及材料版本对应 |
| RAW 加工中 | 当前 run 的真实阶段事件及前置产物 |
| 等待讨论 | 当前 run discussion/awaiting、awaiting_dialogue、实际 Wiki 和讨论底稿 |
| Wiki 已归纳 | 当前 run finalize/completed、finalized 和实际产物 |
| fanOS 已晋升 | 上述Wiki完成、当前run promoted及核验回执；具体笔记/看板的写后哈希、来源/Wiki/看板回链一致 |
| Wiki 已归纳，晋升需核对 | Wiki完成仍保留；晋升回执、目标、哈希或回链缺失/变化，不覆盖用户内容 |
| 接续需检查 | 原件/快照变化、产物缺失、版本未对应、阶段不完整或非法路径 |

读取限两条固定状态流及其中明确列出的08产物；晋升仅增加08核验回执列明且已通过路径检查的非Rocker目标文件，不扫描整个Vault。旧 run 成功不遮盖新 run 失败，同一 PDF 的旧转换稿成功不自动证明新转换稿完成。来源档案未对应当前材料身份和版本时提示比较提取稿，按正式协议明确选择是否重编译。

晋升核验回执位于 `08_LLM Wiki/logs/promotions/<runId>.json`，包含schema=1、sourceId、runId、授权原文，以及targets中的path、写后SHA-256、role=note或board。它由Claudian在明确目标授权、实际保存和回填后写入；不改变正式RAW事件协议，也不扩大写入权限。用户后来编辑目标时需重新核对及补存新哈希，工作台保留修改并提示，不自动重写。

## 字幕接口的实际边界

`POST /v1/transcript` 支持 YouTube/B站的公开字幕入口，需要材料服务 Bearer，返回 Material，**不写订阅 feed**。保留原始字幕对象或字幕文件，输出带时间段的 Markdown，始终标为 partial，注明语言、自动字幕及画面缺口。当前第一分P之外、X/其他平台视频、无公开字幕或需登录场景，需要外部文字稿；没有自动下载音视频或启用付费语音转写。

2026-10-12的YouTube真实请求返回登录/反机器人HTTP400，未取得平台字幕。真实视频接续验收使用[作者公开字幕固定提交](https://github.com/3b1b/captions/blob/9aef876b0ed62ce4f099c0a2f0e7a52e8d1058c9/2017/neural-networks/english/captions.srt)。B站公开字幕分支通过契约检查与单元样本，尚无真实字幕成功回执。当前材料后台包含此端点；v0.13.1时的冷启动及再次重启另有验收记录。

## 验证与维护

接续初验见v0.13.0，收尾见v0.13.1验收与对抗式审查，设置保护见v0.13.2专项。以下为开发验收入口；接续、讨论与晋升脚本可能调用真实Claudian模型并写测试Wiki，日常使用无需重跑。

- `npm run verify`：类型检查、测试、插件和服务构建。
- `npm run verify:claudian-compatibility`：独立 Obsidian 中复制当前 Claudian 三程序，核对验证按钮、回执保存/重载、升级失效、接口/存储失败及键盘窄屏；拦截原生模型发送，不加工正式材料。
- `npm run verify:knowledge-obsidian`：真实文章登记、同条目去重、重启恢复和原阅读库保护。
- `npm run verify:knowledge-video`：作者真实字幕的全量接续，固定原件哈希。
- `npm run verify:knowledge-finalize`：隔离模拟讨论及 Wiki 归纳，不把测试意见当个人观点。
- `npm run verify:direct-wiki-ui`：界面入口与既有阅读保护，不调用真实模型。
- `npm run verify:direct-wiki`：隔离链接/文件/详情按钮与一次真实 Claudian 直达；核对 discussion skipped、finalize、来源原件与批注保护，不写真实库。
- `npm run verify:transcript-http`：鉴权、非法平台、真实字幕失败与订阅 feed 不变。


视频最终归纳、fanOS具体隔离目标的预览/写入/回填及异常会话恢复已实测。真实库知识加工、Wiki周期维护和大量跨日任务的长期使用体验仍需按实际结果核验；首次插件接入不代替这些结果。
