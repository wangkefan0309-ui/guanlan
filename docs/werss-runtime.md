## 固定环境

采集端使用 [WeRSS 上游源码](https://github.com/rachelos/we-mp-rss/tree/9b40351fd1913e7f74cf88f65740cd67a28baf81)，固定提交 `9b40351fd1913e7f74cf88f65740cd67a28baf81`，MIT 许可。源码位于 `.local/collection/we-mp-rss`，原有受版本管理文件保持不变。AIHOT 的固定参考库也保持不变；信息源材料入口仍使用此前从 AIHOT 改造的 RSS 模块。

Python 3.13.15、独立 venv、87 个固定依赖及 Playwright WebKit 浏览器均放在项目 `.local/collection`。安装使用本机已有的 `py -3 -m uv`，不安装 Docker，不改系统 Python 注册表或 PATH。锁定依赖见 `scripts/collection/requirements.lock`。其他机器需先具备 Python 启动器、uv 和 Git。

Windows 下，固定版本的 `PlaywrightController.start_browser` 强制选择 Chromium 时会引用尚未赋值的 `CHROME_PATH`。本项目选择上游已支持的 WebKit，并通过实际生成微信登录码验证；没有改写上游函数。

## 开发者操作

在项目目录运行：

```powershell
npm run collection:setup
npm run collection:start
npm run collection:status
npm run collection:qr
```

当前授权有效，无需重复运行 qr。新环境完成扫码后，由开发助手继续执行：

```powershell
npm run collection:connect
npm run collection:stop
npm run collection:start
npm run collection:attach
```

connect 通过上游 HTTP API 精确匹配五个登记账号；已有账号保留，身份不符或暂停时拒绝替换。绑定保存在 `.local/collection/bindings.json`，采集端启动时加载。attach 连接默认 27183 材料服务，保留已有默认板块，并拒绝覆盖不同的非空更新链接；材料服务需先启动。五个受保护 feed 使用 `/_workbench/feed/WX-001` 等路径，出错返回 HTTP 503 和固定错误码，不把上游错误当成空 RSS 成功。

setup 固定源码版本并核对源码无修改、准备项目内 Python/依赖/浏览器，重复执行保留配置和凭据。start 检查端口和本项目实例身份，已经启动时复用原进程，并验证随机生成的管理员凭据确实能登录。采集端只监听 `http://127.0.0.1:8001`；独立材料服务仍为 `http://127.0.0.1:27183`，两者需要分别启动。

qr 调用真实微信授权流程，将图片保存为 `.local/collection/wechat-login.png`。用户只需用管理公众号的微信扫码并在手机确认；遇到选账号时选择有管理权限的公众号。二维码过期后再次运行 qr；旧预览先移除，生成失败不会把旧预览当作成功结果。扫码后仍需核对有效登录状态、五个 biz、正文回执与更新周期。

qr 同时返回本机授权页地址。授权页提供“显示登录码”、状态检查及本轮结束后的刷新操作，无需输入管理密码；可以稍后再打开使用。页面使用随机访问标识，只有二维码相关操作，不暴露管理密码、JWT、Cookie 或微信 Token；跨站请求拒绝生成二维码。上游登录线程退出但遗留旧图片时，先确认线程已结束再清除旧图并生成新码，避免反复展示过期图片。扫码确认后还须取得持久化 Token/Cookie，才显示“已确认登录”。

固定版本将登录状态保存为 `cookie` 字符串而非浏览器 `cookies` 数组。本项目核对 Token、Cookie 和有限的未来到期时间，启动后恢复上游内存状态；已有有效授权时授权页显示“已登录”并隐藏二维码。这是本次真实登录后修复并运行验证的行为。

本机管理员凭据、服务签名与控制密钥位于 `.local/collection/credentials.json`，不进入源码库，也不输出到命令行。WeRSS 管理页面仍使用它自己的登录流程。普通用户无需手动填写这些凭据。

```powershell
npm run collection:stop
npm run verify:collection
```

stop 仅操作身份、创建时间和命令均核对成功的本项目进程，以及启动时捕获的子进程。停止前请等采集任务完成；超出退出等待时间时会终止进程，未完成的抓取须重新核对回执。verify:collection 会实际停止并重启采集端，只在无真实抓取进行时运行；手机扫码期间也不要运行，以免打断授权。

`npm run verify:collection-ui` 使用真实浏览器访问授权页和只读状态页，检查按钮、CSP、五个真实账号的回执显示；未授权时生成二维码，已有有效授权时验证已登录提示并不生成新码。另用模拟状态验证窗口缺口、恢复和服务不可达显示，模拟结果不算实采。`verify:collection-unit` 运行本项目 25 项适配单元测试，不运行上游测试。

在 Obsidian 左侧点击“查看采集状态 ↗”，或打开 `http://127.0.0.1:8001/_workbench/status`。页面每 15 秒只读取本机 health，展示实际目录计数、最近尝试/保存和最早可再次检查时间；由于账号轮换，实际请求可晚于该时间。账号目录计数不等于材料服务或阅读库中的正文数量。页面不包含扫码凭据、管理员密钥或触发微信请求的操作。

## 发现任务与失败恢复

本项目在独立线程中读取微信文章列表，每页 5 条，每轮最多 6 页 / 30 条。未到边界时 5 分钟后继续下一页，遇到末页或上一轮 head_ids 后每小时检查；达到上限仍未到边界时标记 window_limit，保留旧边界，下轮从最新窗口重新检查。更早历史暂不回补，状态页明确显示缺口。整页核对响应码、列表、原链接 biz、唯一 ID 和发布时间，再以 SQLite 事务保存元数据；缺标题允许按发布日期生成占位标题，不把摘要推断为正文。正文由材料服务从原页面提取，未取得正文不确认材料。

保存成功才推进页偏移；抓取/事务失败仍重试同一页，重启保留已保存页。回执写入失败会停止后续请求并显示 storage_error，先检查存储及诊断，再正常重启。旧版本状态兼容升级，保留退避，下一次从最近尝试账号的后一个开始。全组请求至少间隔 120 秒，一次 tick 最多一页，账号轮换。

采集端 RSS 当前输出最近 30 条目录；正文长期失败且后续发文超过该窗口时，窗口外未保存正文尚无独立队列保证回补。目录事务成功只证明目录已存，正文和连续覆盖必须分别验收。

遇到 200013 暂停整组微信请求 30 分钟，并保存 `.local/collection/discovery.json`；其他错误延后 5 分钟。后台每 30 秒检查到期任务。授权失效和整组错误会盖过旧成功状态；feed 继续显示错误，既有材料保留。各账号的独立尝试与整组错误分别统计，详见本文运行快照。

使用该发现任务时不启动上游的定时任务和正文补抓任务，不使用其长时间阻塞的 `/mps/update` 或可能涉及自身发文的回退端点。上游源码保持不变。分页与恢复已通过模拟测试，真实分页、动态发文导致的偏移变化/漏抓、连续更新与完整正文仍待实采验收。退避不解决接口关闭或持续受限；材料服务手动检查只读取本机回执，不绕过微信退避。后续路线需先验证可用来源，见 [AIHOT 路线复核](aihot-reuse.md#2026-10-10-取阅购买前的公众号路线复核历史)。

## 数据和故障

完整备份 `.local/collection/credentials.json`、`config.yaml`、`bindings.json`、`discovery.json` 和 `we-mp-rss/data/`。后者包含 SQLite 数据库、登录状态和缓存；运行中直接复制 SQLite 主文件可能漏掉 WAL，先停止写入或使用 SQLite backup API。登录文件 `wx.lic` 含敏感授权，按凭据管理，不能分享或提交 Git。未确认授权可恢复前，保留整组数据和加密密钥。本轮升级前已使用 SQLite backup 并保存同组配置/授权到忽略的 backups 目录。

本项目避开上游 main.py 的环境变量全量输出，并在导入上游之前关闭其 stdout/stderr，避免 SQL 参数、Token 或 Cookie 进入终端和共享日志。启动异常的 `diagnostic.json` 仅保存异常类型和代码位置；排障时根据对应代码位置定位，不能据此宣称已经完整记录抓取失败原因。实际抓取回执仍应从 API 和材料账本核对。

启动发现其他服务占据 8001 或身份不符时停止，不关闭其他服务。未授权、正文为空、验证页和抓取失败均不能算订阅验收成功。当前没有购买接口、启用外发通知或配置模型。关机持续运行、真实账号持续更新和热点精选另行开发与验收。
