# 当前订阅采集接入

v0.22.5将网络连接、超时和上游HTTP408/5xx的失败重试改为1、2、5、10、15分钟，连续失败最多等待15分钟；授权、限流、风控及写入问题分别分类，不使用这套快速重试。网络恢复或代理切换后的补检查只提前处理至少一分钟前失败的网络来源，其他来源仍遵守原到期时间。每个来源保留最近12次检查和独立的最近失败记录，成功后仍可追查，记录隐藏URL和凭据。旧回执没有的历史不会补造。

来讯和信源新增“检查并同步”，检查到期来源及符合恢复条件的网络失败来源，先同步已有材料，本轮采集结束后再同步新材料。一次最多跟踪三分钟，超时显示后台仍在采集；现有自动同步继续按配置工作。相同连接及阅读目录的重复点击合并，不调用模型。“同步已采集材料”仅取后台已保存内容；订阅设置中的“立即检查更新”仍为显式强制检查。网络暂不可用时无需例行打开取阅网页或重新保存Google密钥。

微信已有空`js_content`容器时可回退`content_noencode`，保留HTML段落与链接，公开付费预览明确不含付费完整正文。feed和原页的网络读取最多各额外重读一次；授权、限流和身份不符不借此重试或放行。重试期限按上文网络与非网络错误分别处理，单轮顺序采集可能延后计划执行，不保证一分钟内恢复。失败原页与识别摘要保存在后台`subscription-snapshots`供诊断；正文、身份、作者日期和实际保存仍逐项核验。

v0.20.0新增[YouTube官方接口与一次性Key配置](youtube-official-api.md)。配置后优先官方公开视频列表，失败继续RSS/主页；未配置保留现有路线。14项启用来源的实际结果与正式Key配置状态分别见当前状态。


v0.19.2保留 `collectionScope=today`，新增 `catchupDays`（0～7，旧配置默认0）。在“管理订阅与分类 → 断线与延迟补收”选择后显式保存，可补收前几天仍在RSS里的遗漏文章，且不早于开始使用日期。当天页面仍只显示作者当天发布的内容，补收文章归入原发布日期。公众号候选核对原文账号、`create_time/ct`及实际正文，未知日期不以抓取时间补齐。历史日期规则见[每日页面与作者日期](daily-updates-v0.15.0-2026-10-13.md)，当前实际策略见项目状态。

“添加来源”粘贴单号RSS或频道/UP主页，识别后选分类、保存；重复来源提示，多个RSSHub origin需先统一。识别不代表实采成功，采集回执看 `/v1/subscriptions` 或工作台“来源订阅”，保存成功后才确认材料和整页检查点。

正常小时检查；网络类失败按上文快速重试，其他失败首次五分钟后渐进退避；后台每30秒检查到期任务，运行中请求合并。每六小时至少一次不带ETag/Last-Modified的完整读取，避免长期沿用条件缓存。保存失败不确认去重指纹；中断重启会继续，已收录内容保留。有效空feed可成功但新增0。Windows登录隐藏启动已安装；关机/休眠暂停，恢复按当前补收窗口检查。插件自动同步开启后在启动/打开及五分钟执行；同步不调用AI。补收依赖上游仍保留条目及原页面可读，超过窗口或未进入RSS的文章不能保证自动恢复。

私密RSS不输出或提交Git；替换地址后保存完整配置及当前revision。正文缺失或身份不符不称成功，已有材料/进度保留。取阅全文条件及补采候选见[接法与费用](source-options.md)；X是[独立兴趣发现渠道](free-x-setup.md)，不计入十五固定订阅。

日常操作见[本机自动化](local-automation.md)、[RSSHub运行](rsshub-runtime.md)、[HTTP接入](integration-guide.md)、[备份恢复](operator-runbook.md)。旧WeRSS扫码五源200013/自动正文0保留于[历史说明](werss-runtime.md)，不依赖该路线或其旧端口/令牌。

视频订阅仍只保存元数据；用户选中后另尝试公开字幕或导入文字稿，主动文件、订阅与推荐通过统一[Claudian接续](knowledge-integration.md)进入RAW/Wiki。平台受限和原稿缺口分别显示，订阅成功不证明字幕成功。
