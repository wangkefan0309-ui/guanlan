# 历史精选

v0.21.0新增工作台“历史精选”页，订阅更新的当天日期页也有入口。默认每天两项，可在“调整每日数量”中设置1～5项，显式保存后生效；当天已经保存的清单沿用首次数量，修改用于后续日期。

候选来自当前阅读目录中北京时间当日之前的全部历史材料，不限制为近七天。排除已读、回收站、验证用途，以及无正文且无可打开链接的记录。文章、PDF、手动材料、已有文字稿和视频原入口均可进入。发布时间未知时按本地保存日期判断是否已成为历史，不填写虚构的发布日期；只有链接的视频仍明确没有文字稿。

选取时先照顾较少进入历史精选的材料。默认两个位置分别兼顾来源优先级、在读状态、已有正向评价，以及更早积压的材料；尽量兼顾不同作者，但不因此跳过最早积压。每天只选一项时按日期交替价值与轮换。较旧的资讯降低价值排序，仍可通过轮换位再次看到。推荐是阅读建议，不代表内容事实已经核实。

未读材料两次推荐至少间隔七天，稍后读至少十四天。持续新增材料时，较早积压也能进入轮换。未读不会因推荐一次就自动标为已读，也不会逐日叠加成越来越长的当天清单。当天读完后不自动补位，其余候选留待后续日期；若首次没有可选材料，不锁死空清单，后续同步后继续检查。

清单只保存原材料的身份、版本、推荐理由和日期，不复制正文、不重新采集，也不调用模型。阅读、视频、批注和进度沿用原路径。快捷“标记已读”按文章更新各版本状态，有未保存的阅读草稿时先拦截。删除后立即隐藏，恢复后仍引用原版本。同篇后来出现新版本不会改变已保存的当天引用。

“历史精选日期”可以回看已生成的清单，已读和回收站材料继续隐藏。电脑或Obsidian关闭时不生成清单，恢复时只准备当天，不追补停用期间的每天推送。

当天已有探索推荐会从历史候选排除；新探索开始前先保存当天历史引用，再排除这些链接，避免同日重复。历史精选失败时显示真实原因，其他材料仍可阅读，可以显式刷新重试。目录或配置有问题时沿用既有写入保护；切换阅读目录不迁移清单。

记录与材料索引一起保存在阅读目录`_工作台/state.json`的`historyDays`中，旧索引无此字段时按空历史兼容读取。每个日期只提交一次非空清单，保存失败不计入已推荐次数。备份恢复需保留完整同组阅读目录及索引，不能只恢复清单引用而缺少材料。

验证命令：`npm run verify:history-highlights`。脚本使用`validation-vault-v0.1`的独立目录、独立材料服务和关闭的模型/自动采集配置，不访问正式Vault或改共享订阅。核心跨日、轮换和保存故障覆盖在`tests/history.test.ts`；模拟跨日与自然长期使用分别记录。
