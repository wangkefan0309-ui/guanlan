# 主动发现与探索推荐

2026-10-19更新，v0.19.1修复公开检索的兴趣长串，并加入近期未读订阅正文作为补充候选。每天目标1～3条，默认上限3（1～12可调）；搜索和筛选仍共用一个日批次。推荐价值与证据覆盖沿用exploration-8。当前安装、自动开关及真实结果见项目状态。原内容发布日期/提交日/更新时间和推荐生成日期分开显示。

2026-10-19排查时，正式回执确认了三项原因：自动探索关闭；中文多板块兴趣被完整拼入Hacker News/GitHub查询，连续零网页结果；2026-10-18免费X也未取得候选。2026-10-15另有旧评分导致的低分排除，但2026-10-18零候选并不是评分造成。旧批次与模型回执保留，不删除或重算来制造恢复结果。

公开技术索引将多板块中文清单改写为按天轮换的单方向查询，保留实际检索词与说明；Hacker News限制近七天提交。综合中文与跨板块发现优先DeepSeek原生联网；X失败不阻断其他渠道。近期七天未读或稍后读、已有实际正文的订阅可补最多六个候选，先排除近30天已推、已拒绝及已读链接，再轮流选取作者，与外部发现一起经过同一模型和价值门槛。补充卡标明来源，可直接阅读保存正文；没有把规则选择冒充AI通过，也不保证所有网络/候选条件下必有足量内容。

## 与历史精选配合

历史精选默认每天两项，独立于探索的1～3条目标。新探索开始前先保存当天历史引用，再将其链接纳入规范化去重；首次历史选取也排除已存在的当天探索推荐。探索恢复首次结果时同样排除当前历史链接，旧日批次与评分保持原样。历史引用保存失败时不越过此步骤发起新的模型筛选，先处理实际错误。规则见[历史精选](history-highlights.md)。

## 按日期查看

醒目日历提供月份、每日数量、前一天/后一天/今天，历史推荐不在日期筛选前截断为30条。archive从同一索引快照返回推荐及日期回执，保留失败、结果未确认和零入选日；现有400日批次上限保留。认知成长收录为cognition。检索说明折叠查看，已完成批次不显示新的付费发现动作；已有首次结果仍允许重试保存。详见v0.16.0验收。

## 发现与筛选

`兴趣及八板块 → 综合网页＋可选X＋近期未读订阅 → 真实正文/链接/原件及有限补读 → 推荐价值、材料覆盖与主归属 → 去重、达标板块和作者搭配 → 用户阅读/观看/收录`

八板块为国内、国际、商业、投资、财经、生活、认知与成长、科技与AI。可开关及筛选，至少保留一个；偏好和学习起点参与评价。池最多24候选，每条主摘选最多2400字符，补读外链另限1600字符；原生联网最多三个web_search、跨天轮换查询方向；网页证据轮流覆盖实际query、至多六页，并可从实页取得完整节目入口。

规则先排除已知超七天/未来发布日期及统计导航；只有标题、时长或互动量等不足以说明具体内容时保留UNKNOWN，全无可评价候选不调用筛选模型。一次模型批次输出PASS/BLOCK/UNKNOWN、news/learning/opinion/tool、必填section、推荐价值评价与编号证据。当前提示 `exploration-8`。

推荐价值使用实质份量、信息增量、个人相关性、学习用途四项，程序按内容类型计算。新闻重增量与兴趣，学习/工具重用途；未知的份量或用途用null，不按零分计入，不拿材料抓取范围推断作品本身质量。预览推荐必须有真实的视频/作品/文章入口，未读的作品份量必须留空；已经取得的内容若明确空泛，仍不入选。

证据依据独立标记为原作者陈述、转述线索或线索不足，不折算成低价值分；原作者陈述不表示已经核实。程序要求**PASS、推荐价值≥60、兴趣相关性≥6，且有具体信息增量或用途**；线索不足、明确空泛、重复及关闭板块继续排除。缺新评价字段/分类、越界或错误引用保存失败回执，不自动重发。评分只是阅读发现判断，不能解释为内容质量百分比或真实性概率。

X帖文每批最多补读三条实际文章/项目外链，每帖一条，沿用公网地址与有界读取保护。外链摘选和原始HTML独立保存，保留帖文、作者日期与视频附件；外链日期不覆盖帖文日期，未成功补读不伪造正文。无法观看的视频不生成内容判断，明确“正文或视频内容尚未评价”；项目介绍、官方公告或主题具体的长视频可作为值得打开的线索。发布者主张、计划开放和实际开放分别表述，不补无依据人物背景。机制和权重见[AIHOT对照](aihot-reuse.md)。

同事件/同一期去重、合格原片优先；独立教程/观点不因关键词合并。已读、回收站、已拒绝及30天内推荐URL排除；已经保存但未读的正文允许作为明确标记的订阅补充。达标不同主归属优先，再按推荐价值补充；补充阶段对已选作者/站点的后续候选使用8分的排序折让，让分数相近的不同作者有机会进入，不改卡片分数或降低入选门槛。明显更强的同作者内容仍可选，没有作者配额。未移植完整向量聚簇、四关系发展图或全网热度。

## 渠道和费用

| 渠道 | 接法 | 已验证与限制 |
| --- | --- | --- |
| DeepSeek原生联网 | 插件直接请求官方Anthropic兼容web_search，沿用官方模型Key | 真实兴趣检索及具体播客通过；联网与筛选分别计模型用量 |
| 公开检索 | 免Key HN/GitHub；本机核对有限公网页面 | 真实网页＋X合并筛选通过；偏技术，未保证中文/生活完整覆盖 |
| 免费X | 默认twscrape，自己的账号，专用登录状态 | 三Top首页实采60帖/9候选；真实AI最终3条X推荐及帖文收录通过 |
| Tavily | 可选Key、固定basic、至多两次搜索 | 本机未配置，无真实接入验收 |
| SocialData | 显式选择的付费备选，保留预算账本 | 最低预充值10美元导致暂停；真实付费调用0，不自动切换 |

X与网页共用总候选池及推荐上限。Top关键词/单帖互动用于发现线索，不代表官方全站热榜；互动量注明观测时间。免费X没有数据API费，AI筛选仍计已有模型费用；取阅、模型及其他费用分开，见[接法与费用](source-options.md#x)。

模型Key只发已选模型端点，材料服务仅核对候选/页面；免费X凭据只在专用本机配置，不写Vault或HTTP请求。公网页面逐跳校验、固定DNS/IP与有界保存，取证可复用已有代理。付费SocialData Key仅明确选择时传已配置材料服务与固定供应商。

## 打开、收录和知识接续

v0.22.2起，已保存正文的推荐卡片常显当前阅读状态，并提供“标记已读”。近期订阅直接复用保存材料；外部推荐收录后也能标记。操作按规范化链接关联材料，保留原文、原件、阅读位置和历史推荐回执；未保存的阅读修改先拦截。未收录或已移入回收站的材料不提供快捷已读，标记不会重新生成推荐。

推荐卡片提供链接、理由、近期线索、引用、缺口和拒绝入口。视频时长/外链来自本条已校验原件，不串用引用帖；无文字稿时仅供发现与观看。X“收录正文”保存已采集本条完整文字及原始API对象，明确不含视频转写、外链全文、回复/线程；普通文章走既有导入。发现板块与阅读topic分别维护；收录按主归属映射当前阅读方向，认知与成长归cognition，符合观点类型的材料可归opinion。

重复收录去重，批注与进度保留；原件缺失/哈希失败阻止收录。用户明确选入后可直接交给Claudian，使用已保存的正文/文字稿与原件，按关联会话完成RAW，可选择先讨论再归纳或“直接写入 Wiki（不讨论）”；原件或正文不足先提示缺口。日常操作见[知识接续](knowledge-integration.md)，免费X缓存收录见[HTTP接入](integration-guide.md)。

## 自动化与恢复

首次配置的“自动探索新内容”仍默认关闭；用户可在探索页显式“开启每日推荐（1–3条）”，同时设置上限3，已有官方DeepSeek连接时选择综合联网。开启后layout-ready、工作台打开、每小时以及窗口重新获得焦点/恢复可见时检查当日批次；新推荐在Obsidian内提示一次，界面常显自动开关、渠道数量和未入选原因。订阅采集与五分钟同步独立。关机/休眠/Obsidian关闭暂停探索，恢复处理当日，不追补停机每天的模型批次。正式配置于2026-10-19按用户要求启用，结果与核验时点见当前状态。

升级后的新批次使用新规则；历史批次保留原评分、推荐及原始回执，不重新解释旧分数，不因升级重发当天已有模型任务。界面分别标明“推荐价值”和“历史AI评分”。

阅读目录保存 `探索推荐/YYYY-MM-DD-批次哈希.md` 和 `_工作台/探索/state.json`、批次日志。日志包含搜索原件、模型原回答和用量；发起前写started，结果先落日志再提交笔记与索引。用户改过笔记保留并报告，保存失败只补首次结果；已落盘日志可重启恢复，未知/仅started不重发。若首次日志和完整索引已证明结果提交完成，笔记属性栏或批注冲突不再留下冗余待保存状态；未提交或摘要不一致时继续保护，详见[架构](architecture.md#兴趣发现)。异步固定原目录、连接与模型配置，不读取整个Vault或私人日记。

材料服务分别保存 `free-x/state.json`、`free-x/receipts/` 与可选付费 `socialdata/`。免费X全实例共享北京时间日批次，最多三个首页、不翻页；缺配置不占新批次，实际尝试失败/未知停止当天。重登/换目录不清空缓存；次日可检查。三次是应用级检查数，SDK初始化/有限重试不计为另外的应用批次；每次Python55秒、Node65秒，插件205秒后仍未知不重发。

## 首次结果的显式本地重校验

v0.19.1修正普通文章/节目候选自身URL被误判缺少预览入口的校验缺陷；已有文字证据的非X页面可用自身链接，X仍需实际附件或外链，纯元数据不放行。对于本日恰因这一错误失败、且首次模型回答已经落盘的批次，可显式“重新校验首次结果（不调用模型）”。先核对原日志哈希和请求身份，再从同一rawModel生成独立recoveries回执；原runs、原失败、原模型配置和原始回答保持原样。归档按日期显示派生结果，保存失败补存首次派生结果，缺原件或未知结果不能借此重发模型。
